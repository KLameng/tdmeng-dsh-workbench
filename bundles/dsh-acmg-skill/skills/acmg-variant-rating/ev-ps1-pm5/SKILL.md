# PS1 / PM5：错义变异的氨基酸改变证据

## 定义（原文）

- **PS1**：与先前已确定为致病性的变异有相同的氨基酸改变。例如：同一密码子，G>C 或 G>T 改变均可导致缬氨酸→亮氨酸的改变。（相同氨基酸，不同核苷酸）
- **PM5**：新的错义突变导致氨基酸变化，此变异之前未曾报道，但在同一位点导致另外一种氨基酸的变异已经确认是致病性的。例如：现在观察到 Arg156Cys，而 Arg156His 是已知致病的。（同一位置突变为不同氨基酸）

## 操作步骤（变异解读查询路径 5.3.2.1 / 5.3.2.2）

### 第 1 步：排除剪切影响
- 变异不影响剪切位点。用 SpliceAI 评估：阈值 >0.2 认为影响剪切；若影响剪切，则不按 PS1/PM5 处理。
- **SpliceAI 来源绑定（v1.2.0 补）**：SpliceAI 阈值及 delta score 定义源自 **Jaganathan K, et al. Predicting splicing from primary sequence with deep learning. Cell 2019;176(3):535-548.e24. PMID: 30661751. DOI: 10.1016/j.cell.2018.12.015**（https://pubmed.ncbi.nlm.nih.gov/30661751/）。官方查询通道：**spliceailookup（https://spliceailookup.broadinstitute.org/）**，走官方 API。
- **阈值口径（关键，源自原论文三档 delta score cutoff）**：原论文给出三档 Δscore 阈值——**0.2（high recall 高召回）/ 0.5（recommended 推荐）/ 0.8（high precision 高精度）**。本技能采用 **>0.2** 对应**高召回档（偏敏感，倾向判定影响剪切、多报）**，不是平衡档；若需更保守的"推荐档"，应以 >0.5 为准并在输出标注。delta score 取该位点 gain/loss of acceptor/donor 四类预测的最大值。

### 第 2 步：查数据库
- 在 ClinVar（https://www.ncbi.nlm.nih.gov/clinvar）、HGMD（目前为 Excel 表）检索同一位置的错义变异。

> **⚠ 同位点错义穷尽检索（硬步骤，v1.3.0 新增——防漏用 PM5，实证 var009 TYR / var010 G6PD / var011 GNE / var013 ATP7B：技能群曾因"查不到"漏计 PM5 导致错义位点偏低）**
> **判定 PM5 前，必须穷尽检索"同一密码子/同一氨基酸位置的其他氨基酸改变"是否已有致病变异，不得以"未检索到"一笔带过或整码跳过。** 固定动作：
> 1. **检索范围（强制多通道）**：ClinVar（本基因 + 该密码子 c./p. 变异）、HGMD、PubMed（`<基因>` + `<密码子/氨基酸位置>` + `missense`）、以及 GeneBe 基础注释的"同蛋白位置其他氨基酸改变"列表——**按同一蛋白质氨基酸位置检索全部 p.XxxN 变体**（如 p.Arg299 下的 Arg299His/Ser/Cys），而非只查本变异本身；
> 2. **同密码子判定**：同一密码子的不同核苷酸导致相同氨基酸 → 走 **PS1**；同一位置不同氨基酸（其他氨基酸改变）且该等位已确立 P/LP → 走 **PM5**；两者同通道一并检索，勿混淆；
> 3. **判定完成闸（写死）**：同位点（含同密码子所有变体）检索未走完 ClinVar+HGMD+PubMed 三通道，或检索结果未逐条列"同位置变异 → 已知分类(P/LP) → 是否同氨基酸/异氨基酸"的，**不得定 PS1/PM5 为不成立**；查到的每个同位置 P/LP 变异须逐条记录 c./p.+来源+分类；确无同位置其他氨基酸 P/LP 变异时才写"查不到，PM5 不成立"。
> **（说明：原检索口径未强制"同密码子全变体穷尽"，导致 TYR 漏补 p.Arg299Ser/Cys(PM5)、G6PD 漏 p.Arg463Ser、GNE 漏同密码子、ATP7B 漏 p.Leu795Arg——现升级为穷尽检索硬步骤。）**

> **⚠ 文献核验 + 可疑文献上报（引用唯一权威）**
> **从 ClinVar/HGMD 检索到的"已知致病变异"及其挂载文献，一律默认为可疑文献**（数据库挂载仅表示相关，不保证变异在标题/摘要/表格中可核验，也可能挂载错误）。**必须执行「可疑文献上报」判定（L1/L2/L3 分级 + 挂载默认可疑 + 强制上报的完整判定标准，唯一以 `ev-variant-literature-patient` 为准），逐条输出 PMID+链接+原因 交用户人工核验，或全文核验通过后，才可作为 PS1/PM5 的"已知致病变异"依据。**
> - 若已知致病变异的支撑来自可疑文献（ClinVar/HGMD 挂载但无法核验全文、或检索命中但未核验到该具体位点），在该文献核验完成前，PS1/PM5 判定须标注"待全文核验"或暂不成立；
> - **未核验到"同位置已知致病错义变异"这一具体事实的文献，不得计入 PS1/PM5 依据**。
> **⚠ 按用途定制提取（v1.3.0 全局，PS1/PM5）：本证据码从文献中必须提取【同位置已知致病变异 + 相同/不同氨基酸改变 + 已知分类(P/LP)】；仅靠标题命中、未在正文/表格核验到具体 c./p. 的同位点变异，按可疑文献上报，核验前 PS1/PM5 标"待全文核验"。相同氨基酸改变走 PS1，不同氨基酸改变走 PM5，不得混淆。**

### 第 2.5 步：同位点同一性核验（硬闸，v1.6.0 新增）

> **核心原则：PS1/PM5 的前提是"两个变异真的在同一个物理位点上"。位点不对齐，整个证据就不成立。**

**核验规则（三条）：**

1. **字面对齐优先**：查到的"同位点已知致病变异"，其 `p.HGVS` 位点编号与送检变异的 `p.HGVS` 位点编号**字面一致**（如都是 p.Arg156），直接采信。

2. **编号不一致时必须双编号映射坐实**：若文献/数据库里的位点编号与送检变异字面不一致（如送检是 p.Leu162，文献写 residues 142；或不同转录本编号差 N 位），**不得默认"旧编号/成熟蛋白编号"就采信**；必须找到**同一篇文献或权威数据库（VariantValidator/ClinVar/命名变异库）同时写出两个编号**（如同时写 p.Leu162_Lys164del 和 traditional 142_144del），才能判定为同一物理位点。
   - 找不到双编号映射 → 该已知致病变异**不计入 PS1/PM5**，标"位点同一性未确认"。

3. **禁止心算偏移对齐**：**禁止靠"信号肽约 N 个氨基酸""转录本差几位"手算去对齐文献位置**——编号偏移必须由文献原文或权威数据库给出双编号映射才算数，不得用估算代替查证。

> **反面判例（APOE 2026-10-24，与 PS4 同源）**：APOE c.480_488del p.Leu162_Lys164del（Tokyo/Maebashi）。摘要写 "residues 142–144"，手算信号肽偏移≈18，认为"差 2 位可能是同一个位点"——实际上 PMID 35761986 白纸黑字写了双编号映射：traditional 142_144 = MANE p.Leu162_Lys164del。正确动作：拿送检 p.HGVS 字面直接搜命名变异，找到双编号映射一次坐实，不是手算偏移。


### 第 3 步：分 PS1 / PM5 判定

**PS1 条件：**
1. ClinVar/HGMD 中存在同一位置引起**相同氨基酸改变**的变异；
2. 待分类位点变异与已知致病错义变异（核苷酸层面）不一致；
3. 已知的错义变异是致病的，且其分类标准**不依赖于 PS1**。
- 降级：已知错义变异仅为可能致病(LP)时，考虑降级为 **PS1_Moderate**，而不是不用。

**PM5 条件：**
1. 变异不影响剪切位点；
2. ClinVar/HGMD 中存在同一位置引起**新的（不同）氨基酸改变**的错义变异；
3. 已报道的错义变异是致病的，且其分类标准**不依赖于 PM5**。

> **⚠ 条件 3 查证绑定（v1.3.2，防用逻辑推理替代实际查证）**：条件 3"已知变异分类不依赖 PM5"**必须实际查证**该已知致病变异的分类依据——列出它实际使用的证据码/支撑文献（如该变异独立由功能实验 PS3、人群频率 PM2、家系共分离 PP1 等定级，非依赖 PM5 自己）。**不得用逻辑推理（如"PM5 只有 Moderate 撑不起 Pathogenic，所以它必有独立证据"）替代查证**；未查证到具体依据 → 该码标"待核验"，收尾 confidence 按"流程完成度不足"强制 low。

### 第 3.5 步：PS1/PM5 VCEP 路由读取协议（v1.4.0 新增，权威源=clingen-vcep 原文）

> **⚠ 有 ClinGen VCEP 文件的基因，其 PS1/PM5 特异规则（PS1 附加条件、PM5 计数档位）一律以 `clingen-vcep/knowledge-base/VCEP-<gene>.md` 的 `#### PS1` / `#### PM5` 段原文为权威源，由本步路由读取，不靠手抄（对标 ev-pm2 路由方案，单一权威源）。** 通用 PS1/PM5 判定（ps1_pm5_band：同/异氨基酸+已知分类升降级）用于**无 VCEP PS1/PM5 特异规则**的基因。

**探查结论（2026-10-20，Windows 重建工作区）**：134 个 VCEP 基因文件 **131 个含 `#### PS1` 段、131 个含 `#### PM5` 段**。形态分布——
- **PS1**：98 个条件式 + 31 个通用 Richards + 2 个档位（SGCA/TP53）。PS1 本质是"本变异与已知致病变异**同氨基酸改变**"的**语义判定**（需查 ClinVar 比对），VCEP 的"特异"主要是**附加条件**（剪接排除、旁系同源扩展如 BRAF/KRAS 类比 RAF1/HRAS、同机制要求如 SGCA 需 SpliceAI≤0.10）——**不做数值引擎**，由本步按原文核验附加条件；
- **PM5**：84 个条件式 + **39 个计数档位**（≥N 个同密码子已知致病错义→档位，如 TP53 ≥2→Strong/1→Moderate/1LP→Supporting、LDLR/BRAF/KRAS ≥2→Strong/1→Moderate）+ 8 个 NA + 3 个无段。**PM5 计数档位可做数值引擎**。

1. **定位 VCEP 文件**：查 `clingen-vcep/knowledge-base/00-索引.md`，定位该基因的 `VCEP-<gene>.md`；
2. **读 PS1 / PM5 段**：打开 `VCEP-<gene>.md`，定位 `#### PS1` 和 `#### PM5` 段（若某段无 → 该基因 VCEP 无该码规则，跳第 4 步）；
3. **判定各段形态**：
   - **PS1（语义判定 + 附加条件）**：本变异与已知致病变异是否**同氨基酸改变**（查 ClinVar 比对）是核心，VCEP 附加条件须一并核验——剪接排除（SpliceAI）、旁系同源扩展（BRAF/KRAS 等类比同源基因同残基）、同机制要求（SGCA 需 SpliceAI≤0.10 排除剪接）、是否不得与 PM5 合用等。按原文档位判 PS1 及档位（P→Strong、LP→Moderate 等，见 VCEP 原文），不喂数值引擎；
   - **PM5 计数档位（39 基因）**：提取档位表，喂引擎 `pm5_vcep_band(n_known, gene, spec)` 做计数比较（spec 形态：`{"type":"band","bands":{"strong":2,"moderate":1,"supporting":1},"unit":"known_pathogenic"}`，从高到低取最高达标档）。**取数前提必须执行**：穷尽检索同密码子已知致病错义变异数（走本技能第 2 步 ClinVar/HGMD/PubMed/GeneBe 多通道），逐条记录 c./p.+来源+分类；VCEP 附加限定（如 TP53 Supporting 需已知 LP 变异带临床数据 PS2/PS4/PP1、BRAF/KRAS Strong 需 ≥2 变异在 ≥5 probands 观察）由执行者判，引擎只做计数主档。输出须标注 `PM5 规则来源=VCEP-<gene>.md（ClinGen VCEP 官方）`；
   - **PM5 条件式（84 基因）**：按原文附加条件核验（BLOSUM、平行同源保守、机制等），不喂数值引擎；
   - **NA / Not applicable** → 该基因 VCEP 声明该码不适用，写"该基因 VCEP 声明该码不适用"，不成立；
   - **无特异规则（纯通用）** → 用通用 PS1/PM5 判定（ps1_pm5_band）。
4. **索引无该基因 / 该基因 VCEP 无 PS1 或 PM5 段** → 回退通用 PS1/PM5 判定，并注明"该基因无 ClinGen VCEP PS1/PM5 规则，用通用判定"。

**阈值选择优先级（写死）**：

1. **VCEP 有 PM5 计数档位** → 一律以 VCEP 原文档位判定（如 TP53 ≥2→Strong/1→Moderate、LDLR/BRAF/KRAS ≥2→Strong/1→Moderate）；
2. **VCEP PS1 有附加条件** → 按原文核验附加条件后判 PS1 及档位；
3. **VCEP 条件式 / 无段** → 用通用 PS1/PM5 判定（ps1_pm5_band）；
4. **VCEP 声明 NA** → 该码不成立；
5. **记录要求**：判定 PS1/PM5 时必须在输出中写明"所用判据（通用/VCEP 官方）"及"该判据来源"，查不到特异规则时写"查不到特异 PS1/PM5 规则，用通用判定"。
6. **铁律**：**不得以"本表没有该基因"为由漏查 VCEP 路由**——评 PS1/PM5 前必先走上述路由（查索引→读 PS1/PM5 段），VCEP 有规则则用 VCEP，确无才回退。**禁止**凭手抄表把某基因判为"无特异规则"。

> **🔧 确定性比较（acmg_evidence.py）**：同密码子已知致病错义计数 vs 档位用 `scripts/acmg_evidence.py` 的 `pm5_vcep_band(n_known, gene, spec)` 确定性输出（spec 为路由读取的 VCEP PM5 档位结构，返回 `PM5_Strong/PM5_Moderate/PM5_Supporting` 或 None）；通用 PS1/PM5 仍用 `ps1_pm5_band(same_aa, known_class, other_p_count)`。用法：`python acmg_evidence.py pm5_vcep_band <N_KNOWN> <GENE> <spec-json>`。

## 强度调节（通用口径，指南解读 slide 33）

| 调节 | 条件 | 结果 |
|---|---|---|
| PS1 下调 | 同一位置引起相同氨基酸改变的变异评级为 LP | PS1_Moderate |
| PM5 下调 | 同一位置突变为其他氨基酸的变异评级为 LP（1 个其他氨基酸为 LP） | PM5_Supporting |
| PM5 通用档位 | 同一位置有 1 个其他氨基酸为致病(P) | PM5_Moderate |

> **⚠ v1.5.0 元素解耦说明**：**"同一位置有 2 个其他氨基酸为 P → PM5_Strong" 是 VCEP 基因特异规则**（TP53/LDLR/BRAF/KRAS 等 39 个 VCEP 基因有此计数档位），**不是通用规则**。通用基因 PM5 最高 Moderate，不得因"有 2 个其他 P"就升 Strong。计数升级统一走 `pm5_vcep_band` 路由读取 VCEP 原文判定，不在通用 `ps1_pm5_band` 函数里。
>
> **反面判例（COL2A1 2026-10-24）**：COL2A1 无 VCEP 文件，按通用=通用铁律，PM5 应为 Moderate(+2)，不该因"同一位点有 2 个其他 P"就升 Strong。之前把 VCEP 计数逻辑泛化进通用函数，导致过度取档。

> **🔧 确定性映射（acmg_evidence.py，替代手工查表）**：通用 PS1/PM5 档位用 `scripts/acmg_evidence.py` 的 `ps1_pm5_band(same_aa, known_class)` 确定性输出（同氨基酸 P→PS1 / LP→PS1_Moderate；异氨基酸 P→PM5_Moderate / LP→PM5_Supporting）。VCEP 基因的计数升级走 `pm5_vcep_band(n_known, gene, spec)`。用法：`import acmg_evidence; acmg_evidence.ps1_pm5_band(False,"P")`。

## 输出格式（强制，本 SKILL 判定完成后必须按此输出）

每个证据码判定完成后，**必须**按下述三点完整输出；缺一不可，查不到的数据明确写 **"查不到"**，严禁用本 SKILL 内的举例数据或推测代替。

### 1. 证据码 + 对应等级
`[证据码]_[使用等级]`，如 `PM3_Strong`、`PP3_Moderate`、`PM2_Supporting`。未成立则写"本证据不成立/弃用"。

### 2. 支持该等级使用的规则性数据内容 + 定级规则
- 写明支撑该等级判定的**具体数据值**（如人群频率、REVEL 分数、反式例数、对照数目、OR 值、分离次数等）；
- 对照本 SKILL 的定级规则/阈值表，说明该数据落在哪个区间/档位，从而定为该等级；
- 即：数据值 → 落入的规则档位 → 所得等级，三步闭环。

### 3. 查询路径
列出本次判定**实际查询过**的数据库链接、文献编号(PMID)及对应链接；**每次查询都必须是真实查询**。
- 数据库：名称 + URL（如 ClinVar、gnomAD、Pubvar、OMIM、HGMD、ClinGen 等）；
- 文献：PMID 编号 + 链接；
- 某项查不到：写 **"查不到"**，不得以举例数据填充。

> **铁律**：本 SKILL 内所有"案例/示例/举例"仅供教学演示，**禁止**作为评级数据套用；评级数据一律来自实际查询，否则该证据码不得计入。
