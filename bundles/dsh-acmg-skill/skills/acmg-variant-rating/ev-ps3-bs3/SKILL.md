# PS3 / BS3：功能实验证据

## 定义（原文）

- **PS3**：体内、体外功能实验已明确会导致基因功能受损的变异。注：功能实验需要验证是有效的，且具有重复性与稳定性。
- **BS3**：体内、体外功能实验已明确证明变异对基因功能无影响（变异解读查询路径 与 PS3 同条对照给出）。

## 操作步骤（SVI 四步流程，指南解读 slide 36）

1. 明确疾病的致病机制；
2. 评估在该领域中使用的一般类型功能实验方法的适用性（该实验能模拟疾病发病机制为前提）；
3. 评估具体案例中功能实验的有效性；
4. 将证据应用于特定变异的解读。

## 有效性与强度判定（变异解读查询路径 5.4.2，指南解读 slide 37）

考察：方法是否得到广泛验证、有无阴性和阳性对照、有无重复实验、有无良性/致病性变异对照、对照数目。

| 情形 | 强度 |
|---|---|
| 没有充分对照，但实验方法已得到广泛验证 | PS3_Supporting 或 BS3_Supporting |
| 充分对照且数目 ≥8 | PS3_Supporting 或 BS3_Supporting |
| 充分对照且数目 ≥11 | PS3_Moderate 或 BS3_Moderate |

> **⚠ P1-2 修正（证据码核对报告 20261021）**：Moderate 档对照数由"≥12"改为"**≥11**"。Brnich 2020（PMID 31892348 / Genome Med 2019;11:75, doi:10.1186/s13073-019-0690-2）Results 原文："We found that a **minimum of 11** total pathogenic and benign variant controls are required to reach moderate-level evidence in the absence of rigorous statistical analysis." 即达 Moderate 需 ≥11 个对照，非 ≥12。

### 第 3.5 步：PS3/BS3 VCEP 基因特异档位路由（v1.7.0 新增，优先于通用表）

> **⚠ 2026-10-20 新增（通用=通用、特异=特异 + PS3 证据本质）**：PS3/BS3 判定**先判断该基因是否有 ClinGen VCEP cspec 且其 PS3/BS3 段定义了可路由的实验分档规则**。有 → **必须路由读 clingen-vcep/VCEP-<gene>.md 的 `#### PS3`（致病侧）/ `#### BS3`（良性侧）段原文**，按原文档位判定，**优先于上方通用对照数目/OddsPath 表**；无 PS3/BS3 段 / 引用式无数值 → 回退上方通用表。
>
> **PS3/BS3 与数值类码（PP3/BP4/PM2 等）的本质差异（写死）**：PS3/BS3 的核心是**"功能实验类型 + 判据 → 档位"**（语义判定，非数值切点）。同一基因的 VCEP 定义了可用的功能实验类型（RNA 剪接 / 酶活% / 电生理 / Kato 分档 / 寡聚化 / GTPase / 免疫荧光 等，各不相同，无法穷举）与各档位的判据（如 GAA 酶活<5%→Moderate、<30%→Supporting；TP53 Kato non-functional+LOF 多数→Strong；CDH1 RNA out-of-frame→Strong、in-frame→Moderate）。**判定时必须按该基因 VCEP 原文识别"用哪个实验类型 + 该实验是否满足判据"，不得套用其它基因的实验类型或通用 OddsPath 档。**

**路由协议（写死，与 ev-pm2 / ev-bs1-bs2 / ev-pp1 / ev-pp3-bp4 同源）**：
1. **查 00-索引**：`clingen-vcep/knowledge-base/00-索引.md` 按基因名定位 VCEP 专家组 → 读取 `clingen-vcep/knowledge-base/VCEP-<gene>.md` 的 `#### PS3` / `#### BS3` 段（数据日期 2026-06-13，路由须排除 `VCEP-verification-evidence.md` 等非基因文件）；
2. **读原文 PS3/BS3 段**：逐档位（**VeryStrong** / **Strong** / **Moderate** / **Supporting**）读取实验类型与判据；
3. **按原文解析 spec + 喂引擎 `ps3_vcep_band`**（确定性比较）：
   - **实验类型识别**（按原文，不得凭记忆）：该基因 VCEP 用哪些功能实验（RNA/酶活/电生理/Kato 等）→ experiments 键名对应；
   - **判据满足**（由执行者核验原文 + 实际实验数据）：数值型判据（酶活%≤X）→ 填数值；语义型判据（out-of-frame / non-functional / LOF 多数）→ 填布尔/枚举；**未核验到该实验判据 → 不得默认该档成立**；
   - **BS3 良性侧**：`benign=True` 走 BS3 前缀；多数基因 BS3 段引"See PS3 specifications"（镜像）→ 按原文判"无损伤效应"；
4. **引擎做确定性比较**：`python scripts/acmg_evidence.py ps3_vcep_band <experiments_json> <GENE> <spec_json>`（或 `import acmg_evidence; acmg_evidence.ps3_vcep_band(...)`），返回 (档位, 依据)；
5. **封顶原则**：VCEP 只定义了某档的基因 → **PS3/BS3 封顶该档**，不升更高档（对齐 PP3/PP4/PS4 封顶，特异=特异）。

> **🔧 确定性定档（acmg_evidence.py，替代手工比较）**：实验判据 vs VCEP 档位的比较统一用 `scripts/acmg_evidence.py` 的 `ps3_vcep_band`，LLM 不再手算。

> **⚠ 与通用表的关系（写死）**：上方通用对照数目/OddsPath 表（SVI 通用口径）仅在"该基因无 VCEP PS3/BS3 特异规则"时使用。**有 VCEP 特异规则的基因一律先走路由**。证据性质核验（§"证据性质核验"）与穷尽检索（§"功能实验穷尽检索专项"）仍是**任何情形下的前置硬步骤**——VCEP 路由只管"用哪个特异切点/实验判据定档"，核验与穷尽检索管"该功能实验是否真正支持本特异变异"，两者并行不冲突。

> **判例（写死，防复发）**：GAA 酶活分档——VCEP GAA PS3：酶活<5%→Moderate、<30%→Supporting（通用 OddsPath 表无此酶活切点）。**必须路由读 VCEP 用 GAA 酶活判据**，测到残余酶活 10% → 按 VCEP 是 PS3_Supporting，不得因 OddsPath 通用表误判为 Moderate/Strong——"通用 over-call、特异收紧"的典型。

### 残余酶活维度判例参考（v1.6.0 降级定位：示例性判例，非通用硬阈值，须按基因/方法逐案核）

> **⚠ 定位声明（v1.6.0，v20 审计 N4 处置）**：下表是**示例性判例参考，不是通用阈值表**——残余酶活百分比的**分母（正常对照均值/下限）、检测体系（成纤维细胞/淋巴细胞/干血斑）、底物、阈值切点各基因/各方法差异很大**（≤5% 在某酶近乎无功能、在另一些酶不成立），**不得做成跨基因统一硬阈值套用**；实际评级须**按该基因/该功能实验方法逐案核**，并以「对照数目/OddsPath」维度与实验质量为准定档。下表仅给出"残余活性越低 → 档位越高"的关系方向参考。

| 残余酶活（示例判例） | 档位参考（须逐案核） |
|---|---|
| ≤5%（几乎无功能） | PS3_Strong |
| 5–30%（部分功能） | PS3_Moderate |
| >30%（轻度受损） | PS3_Supporting |

> **本表只适用「酶活/功能活性类功能实验」（酶病/代谢病基因，直接测残余酶活/催化活性）**，不套用剪接/RNA/转运/信号通路等非酶活实验；是**残余活性单一维度的判例参考**，与「对照数目/OddsPath」维度**叠加**共同定档，不替代、不单独决定档位；强度还须叠加实验质量（金标准方法、可核验）+ 独立文献数。**引擎不感知酶活数据**（PS3 档位由技能层判定，本表为判例指引、非确定性门禁——如实声明，不为它强造引擎门禁）。

> **叠加纪律（写死，防机械套表引入新问题）**：残余酶活映射是必要条件之一，还需：①实验针对本特异变异（见下方「证据性质核验」第1条）；②有阳/阴性对照——**无充分对照的单篇生化仍最高 PS3_Supporting**（见上方「有效性与强度判定」表，不被本映射顶到 Strong）；③方法已广泛验证（金标准方法）；④**阈值须按该基因/该方法逐案核，不得套作跨基因统一硬阈值**。任一不满足 → 按较低档，不以残余酶活百分比单点升档。

### 结果冲突时（变异解读查询路径 p18）

- 不同验证方法结果一致（均异常 / 均正常）→ 应用 PS3 / BS3。
- 结果相互矛盾：最能反映疾病机制且最有效的验证方法可替代冲突结果；若验证方法水平相同、结果矛盾，则该功能证据**不应用于**解读变异。
- 避免重复计算：仅考虑进化保守或物理预测（晶体结构）的体外酶活测定应取代预测；剪接预测可用 PP3，但若有实验室证据表明剪接异常或蛋白功能异常，应使用更强的功能证据。

## 证据性质核验（强制，启用 PS3/BS3 前必须确认，防误用）

**在应用 PS3/BS3 前，须核验该功能实验是否真正支持"本特异变异"的功能受损/无影响：**

> **⚠ 文献核验 + 可疑文献上报（引用唯一权威，先核验再采信功能实验）**
> **PS3/BS3 依赖的每一篇功能实验文献，须调用 `ev-variant-literature-patient` 完成「可疑文献上报」判定（L1/L2/L3 分级 + 挂载默认可疑 + 强制上报的完整判定标准，唯一以该技能为准），再决定是否采信；判定输出须含"本次计入文献核验等级"。**
> **⚠ 按用途定制提取（v1.3.0 全局，PS3/BS3）：本证据码从文献中必须提取【实验方法 + 是否针对本特异变异 + 阳/阴性对照 + 受损/无影响结果】；功能实验非针对本特异变异（如携带者队列关联测量），不得用 PS3（SMPD1 判例）。缺对照的单篇生化研究最高 PS3_Supporting。关键字段提取不到，标"未报告/非本变异实验"，不得凭推测填充。**


1. **是否针对本特异变异**：该功能实验是否直接测了**本变异的氨基酸改变**（同一蛋白位点），而非同一基因其他变异、或携带者队列的关联测量。**反证判例（SMPD1）**：ClinVar curated 提交明言"no experimental evidence demonstrating impact on protein function"，所谓"酶活"来自帕金森携带者队列关联测量（PMID 38291878/39572736），**非该变异的成熟体外功能实验** → 不得用 PS3。
2. **是否验证了阳性和阴性对照**：按 SVI 建议，PS3 需实验对照已知致病变异 AND 已知良性变异；无此验证的**单篇生化研究最高到 PS3_Supporting**（不是 Moderate/Strong）。
3. **单次过表达/定性"活性下降"是否足以定 Strong**：单次过表达、仅定性活性下降的实验（如 COS-1 过表达仅"活性下降"），**宜 Supporting/Moderate，不宜 Strong**（对应 GALC 教训）。
4. **是否与该基因 LOF 证据冲突**：截短变异若已由基因 LOF 致病机制覆盖，不应再以功能实验重复计 PS3（防重复计算）。

## 功能实验穷尽检索专项（硬步骤，v1.3.0 新增，防漏检）

> **本专项对治"功能实验文献未检索到而漏计 PS3"（实证 var010 GALC COS-1 酶活 PMID 9272171 / var036 SLC22A5 HEK293T 转运 PMID 16931768 / var037 G6PD 已确立缺乏变异型——金标准核验到这些成熟功能实验，技能群未检索到而 PS3 漏计，均为偏低根因）。** 判定 PS3/BS3 前，**必须**完成穷尽检索，不得只凭 ClinVar/HGMD 挂载或单篇文献：

1. **去哪查（多通道并行）**：
   - **PubMed**：`<gene>` + `<变异HGVS/氨基酸改变>` + 下列关键词各组合——`functional assay`、`enzyme activity`、`activity`、`transport`、`expression`、`catalytic`、`luciferase`、`cell-based`、`knock-in`、`cell line`；
   - **ClinVar**：读该变异/该位点的提交注释，查是否标注功能实验结果（注明 PMID 与实验类型）；
   - **HGMD / 内部库**（如可用）。
2. **查什么**：**逐篇核实是否"成熟体外/体内功能实验直接测了本变异（同一蛋白位点的氨基酸改变）"，并提取【实验方法 + 是否针对本特异变异 + 阳/阴性对照 + 受损/无影响结果 + 对照数目】**；只检索到携带者队列关联测量或同基因其他变异实验，不算针对本变异的成熟功能实验。
3. **看到啥算数**：核验到针对本变异的成熟功能实验（酶活/转运/荧光/细胞增殖等，有对照），按 §"有效性与强度判定"表定档；单篇定性/缺对照生化实验最高 PS3_Supporting。
4. **输出"功能实验检索结果表"**：| 文献(PMID) | 实验方法 | 是否针对本变异 | 对照/数目 | 结果(受损/无影响) | 定档 |，每项查不到写"查不到"。**检索缺口即漏计风险，不得因"ClinVar/HGMD 未挂载"默认无功能实验而弃用 PS3。**

## 互斥裁决（移交收尾技能，本技能不执行）

按全局约束：**互斥原则只在收尾技能 `acmg-conflict-summary-output` 统一裁决**，证据码子技能不做互斥、不预判取舍。本技能只做 PS3/BS3 自身功能实验判定，**不因与 PM1/PM4/PP3 等码互斥而弃用、降档或拒用 PS3/BS3**；是否保留/弃用（含 PS3 与 PP3 同存时的取舍）由收尾技能按证据强度与互斥矩阵 §1.2 统一裁决。**本技能不再内嵌"PS3 优先保留"等取舍结论**——取舍是收尾的裁决职责，不在此预判。

每个证据码判定完成后，**必须**按下述三点完整输出；缺一不可，查不到的数据明确写 **"查不到"**，严禁用本 SKILL 内的举例数据或推测代替。

### 1. 证据码 + 对应等级
`[证据码]_[使用等级]`，如 `PM3_Strong`、`PP3_Moderate`、`PM2_Supporting`。未成立则写"本证据不成立/弃用"。

- 即：数据值 → 落入的规则档位 → 所得等级，三步闭环。
