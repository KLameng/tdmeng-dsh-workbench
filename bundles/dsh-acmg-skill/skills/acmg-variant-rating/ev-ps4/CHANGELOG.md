# ev-ps4 CHANGELOG

## v1.5.0（等价位点同一性核验闸门，2026-10-24 APOE 判例复盘）

- **新增第 0.5 步：等价位点同一性核验（硬闸门，数先证者前必过）**——PS4 的数学是"同一物理变异在患者中富集"，位点不同则富集不成立。
- **四条硬规则**：
  1. 先字面对齐，禁止心算偏移：拿送检 p.HGVS/c.HGVS 原样反查 PubMed/ClinVar/VariantValidator，优先查命名变异别名；禁止靠"信号肽约 18aa""转录本差几位"手算对齐文献位置。
  2. 编号差 N 位时的坐实条件：文献氨基酸位置与送检 p.HGVS 不一致时，必须找到同一篇文献或权威数据库同时写出两个编号（双编号映射），才能判定为同一变异；找不到则该文献不计入 PS4。
  3. 模糊摘要不得计分：摘要只写"9bp 缺失""3aa 缺失""exon4 突变"而无精确位置时，标 L2 待全文核验，拿到全文/双编号映射前不得计入先证者数。
  4. 同基因邻近变异排重：同一功能域内多个位置相近的不同 indel/SNV（尤其重复区），须逐篇核对精确位置是否物理重合，相邻但不重合的不得合并计数。
- **反面判例（APOE 2026-10-24，写死防复发）**：APOE c.480_488del p.Leu162_Lys164del（Tokyo/Maebashi）。第一轮错误：摘要写"residues 142–144"，手算信号肽偏移≈18，认为"可能是同一变异但对不齐"，标成待核验，PS4 只敢给 Supporting。实际真相：传统编号 142_144 对应 MANE 的 Leu162_Lys164，PMID 35761986 有双编号映射。正确动作：拿 `p.Leu162_Lys164del` 或 `APOE Tokyo` 直接搜 PubMed，一次命中坐实。
- **自检清单新增一条**：已完成等价位点同一性核验——每篇计入 PS4 的文献都有 p.HGVS/c.HGVS 字面命中或双编号映射，未用心算信号肽偏移对齐。
- 纯流程层改动，不改引擎、不改 VCEP 阈值表、不改通用档位表。

## v1.4.0（PS4 VCEP 基因特异档位路由 + 先查数值后匹配，2026-10-20）

- **撤原手抄 VCEP 表**（MYH7/RASopathy/PTEN/CDH1/HL 5 键）——与 PM2/BS1/PP1/PP3/PM3/PP4 一致，特异基因档位改为路由读 clingen-vcep/VCEP-<gene>.md 的 `#### PS4` 段原文（单一权威源，不落库制造副本）。引擎 `acmg_evidence.py::PS4_VCEP` 常量已删，`ps4_band` 收敛为纯通用 ≥2/≥6/≥15 分支。
- **新增第 3.5 步 VCEP 基因特异档位路由协议**：PS4 判定先查 clingen-vcep/VCEP-<gene>.md `#### PS4` 段原文规则，按该基因特异档位定档，优先于通用口径。
- **PS4 证据本质澄清（用户确认 2026-10-20，同 PP4）**：PS4 是"**先查文献/临床数据拿数值 → 再拿数值对照 VCEP 特异规则匹配档位**"的证据链。VCEP 规则只定义"多少数值→哪档"，数值本身须执行者先查取（先证者/家系数、表型点数、OR/CI、病例对照队列数据）。取不到数值写"查不到"，不得默认给档。
- **新增引擎 `acmg_evidence.py::ps4_vcep_band`**：支持 count 计数型（ABCD1/ACVRL1/ENG/CDH1/F8/F9/LDLR 等）、points 点数型（APC/PTEN/FBN1/DICER1/FOXN1/IL2RG/AKT3/MTOR 等）+ phenotype 条件式回退（MYH7/MYBPC3/ATM/BRCA1/BRCA2 等病例对照 OR+CI，引擎不判数值，返回需执行者按原文核统计条件）；spec 缺省→通用口径；max_band 封顶。
- **PS4 形态分布（106 含 PS4 段基因，全量探查）**：①计数型（29，先证者/家系/病例数）；②点数型（39，表型评分，APC/PTEN/FBN1/DICER1 等）；③病例对照/条件式（37，MYH7/MYBPC3/BRCA/ATM/HBB/HBA2 等）；④模板/其他（1）。
- 与 v1.3.0 通用先证者数规则一致（通用基因行为零变化）；未引入新矛盾，特异=特异、通用=通用。

## v1.3.0（PM3–PS4 不重复计入，2026-10-16 用户复盘"PS4 与 PM3 重复计入同一批先证者"）

- **根因**：AR 病罕见变异场景下，PM3 逐例累分已用全部患者，PS4 再说"患者富集"是同一批人重复算两次。
- **第 1 步 AD/XL 补「与 PM3 不重复计入」**（呼应收尾 §1.1 软提醒）：PM3 已逐例累分的患者不得再作 PS4 先证者/富集来源；PS4 仅在有**独立**病例对照/队列统计（AR 须 OR>5.0 且 CI 不含 1.0，或 AD/XL 独立先证者数）时成立；仅文献零散报道或与 PM3 同一批患者不构成 PS4 独立富集证据。
- 纯流程/契约层改动，不改引擎、不改 VCEP 阈值表。

## v1.2.3（PS4 先证者独立性核对，2026-10-16 用户复盘"争议实为跳步"）

- **根因**：评级实证——PS4 患者数未查 ClinVar SCV submission 详情，直接"3 提交≈3 无亲缘患者"推断。
- **第 1 步 AD/XL 补"先证者独立性核对"**：须核对各 SCV submission 是否无亲缘/独立，多个提交可能指向同一患者或同一家系，按患者/家系去重后再计数；无法确认独立按"疑同源（无法确认），保守合并"标注。先证者数逐篇核对、不重复计数。
- 纯流程/契约层改动，不改 VCEP 阈值表、不引擎。
