# 架构决策记录（ADR）

本目录记录技能群的关键架构决策，供后续维护者追溯"为什么这么做"。

## ADR 编号与映射

- 每条 ADR 有唯一编号 `ADR-<N>`；
- 与 CHANGELOG 中对应的版本/条目（D/P 编号）建立映射表，见各技能 `CHANGELOG.md`；
- 新决策必须先记 ADR，再动实现。

## 一条 ADR 的模板

```
# ADR-<N>：<标题>

- 状态：<提议 / 已接受 / 已替代 / 已废弃>
- 日期：YYYY-MM-DD
- 关联 CHANGELOG：v<X.Y.Z> 的 <D/P> 条目

## 背景
（为什么要做这个决策）

## 决策
（定了什么）

## 后果
（正面/负面影响，替代方案为何被否）
```

## 关键决策索引（随项目维护）

- **ADR-1 技能群定位**：技能群只走评级流程，结论由人工定级；评测核心 = 指南忠实度。
- **ADR-2 两池架构**：评级池（指南合规，进引擎）+ 提示池（指南外相关性，人工弹性证据）。
- **ADR-3 争议证据码口径**：金标准固定确信；评级/归档如实展示、争议证据码原样保留；分歧作能力诊断信号。
- **ADR-4 互斥信息收敛**：证据互斥只存于收尾技能 `acmg-conflict-summary-output`，ev-* 子技能不携带。
- **ADR-5 版本命名策略**：主版本用概括性名称（核心差异），版本内优化用数字 `.1/.2/.3`。

> 每新增一条关键决策，在本索引追加一行，并在对应技能 CHANGELOG 记映射。
