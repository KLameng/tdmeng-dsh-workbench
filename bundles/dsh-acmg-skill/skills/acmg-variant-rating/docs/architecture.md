# 架构（architecture.md）

> 目标：给出技能群的**平台无关编排**视图，说明各层职责与数据流，供维护者理解全貌、避免在错误层做改动。

## 分层结构

```
┌─────────────────────────────────────────────────────────┐
│ 调度层 acmg-total-scheduler（唯一入口）                    │
│   变异身份归一化 → 遗传方式前置判定 → 圈定证据码池          │
└───────────────┬─────────────────────────────────────────┘
                ▼
┌─────────────────────────────────────────────────────────┐
│ 证据码子技能 ev-*（逐码判定）                             │
│   PM2/PM3/PP1/PS1… 各自按指南判定，参数/路径/版本可追溯     │
│   铁律：子技能不携带任何证据互斥内容                        │
└───────────────┬─────────────────────────────────────────┘
                ▼
┌─────────────────────────────────────────────────────────┐
│ 收尾层 acmg-conflict-summary-output                      │
│   互斥消解（唯一互斥矩阵所在）→ 两池分流 → 输出              │
└───────────────┬─────────────────────────────────────────┘
                ▼
┌─────────────────────────────────────────────────────────┐
│ 组合引擎 acmg_combine.py（确定性）                        │
│   表5 等级组合 + Tavtigian 分值 双套并列，不取值归一         │
└─────────────────────────────────────────────────────────┘
```

## 两池输出（ADR-2）

- **评级池**：严格按指南流程产出的证据（合规）→ 进引擎参与评级；
- **提示池**：不合指南使用规范、但有参考价值的相关性信息 → 不参与评级，作人工最终评估的弹性证据。

## 数据流与确定性

1. 调度层圈定可用证据码池（按变异类型）；
2. 各子技能逐码判定，输出**查询路径 + 参数 + 结论**（留痕）；
3. 收尾层按互斥矩阵消解、分流两池；
4. 引擎按最终使用等级分桶定级（两套并列）；
5. **结论由人工核验定级**，技能群不输出最终临床结论。

## 平台无关编排（对照 DSH 依赖）

- 技能群核心评级逻辑**只依赖 Python 标准库**，可在多平台/多运行时直接运行；
- 外部依赖（`requests`、`pyliftover`）仅在涉及网络/坐标转换的子技能启用，见 `requirements.txt`；
- **确定性脚本优先**：凡可固化的判定（引擎、门禁、契约、回归）不依赖 LLM 自由裁定；
- 豆包运行时提供的既有依赖（如 `dsh`）作为**可选宿主**，不成为核心逻辑的硬依赖，保证技能群可独立部署。

## 关键不变式（铁律）

- 证据互斥只存在于收尾技能；子技能不携带互斥；
- golden.json（评测输入）冻结不动，是基准非被测对象；
- 争议证据码原样保留、如实展示，分歧作能力诊断信号；
- 对外只称"双引擎自洽率"，不称"准确率"。
