# 发布 SOP（release-sop.md）

> 发布技能群版本的固定流程。**按此顺序，缺一步不算发布。**

## 版本命名策略（ADR-5）

- **主版本 = 概括性名称**：一看到就知道这版核心差异（如本次升级 = **工程体系建立完成版**）；
- **版本内优化 = 数字 `.1/.2/.3`**：同一概括版内的小优化用数字递增。

示例：
```
v1.2.0 · 工程体系建立完成版   ← 本次升级（对外 v1.2.0）
v1.2.1 / v1.2.2 ...            ← 该版内的小优化
v1.3.0 · <新的概括名>          ← 下一个大里程碑（核心差异变了才换名）
```

## 发布流程（按序）

1. **定版前核对 VCEP 数据是否最新**：用 `scripts/check_vcep_version.py` 核对挂载库版本，并**记录"技能群版本 ↔ VCEP 数据版本"关联**；
2. **确认 KNOWN_ISSUES 无未关闭的 P0**；
3. **门禁全过**：回归门禁 / 契约测试 / py_compile / 结构检查（含 VCEP 数据层，从独立数据仓库拉取）；
4. **流程合规自检**：评测口径已确认、双引擎自洽率记录口径一致；
5. **build**：`scripts/build_package.py` 打包；
6. **manifest**：`scripts/make_manifest.py`（哈希锁，**在 build 之后**，MANIFEST 含 VCEP 版本关联）；
7. **upload**：上传产物；
8. **收尾**：同步升版本号（frontmatter/CHANGELOG/README）、追加开源事件台账、评估副本同步（若涉及引擎改动）。

## 收尾义务（不可省）

- 改任何子技能正文 → 升 frontmatter 版本 + 记该技能 CHANGELOG；
- 引擎改动 → 更新文件头版本号并留痕；
- 开源事件（发布/升级）→ 追加至开源事件台账。
